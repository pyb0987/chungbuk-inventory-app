# 충북사무소 재고관리 앱

삼촌의 업무를 돕기 위해 만든 로컬 재고관리 앱입니다.

기존에는 `재고현황` 엑셀과 `사용내역/부품신청서` 엑셀이 따로 관리되어, 한쪽에 입력한 내용이 다른 파일에 바로 반영되지 않는 문제가 있었습니다. 이 앱은 그 흐름을 하나로 모아, 재고 확인과 입출고 기록을 같은 화면에서 처리할 수 있게 만든 작은 업무 도구입니다.

## 이 앱이 돕는 일

- 현재 재고를 엑셀에서 가져와 시작합니다.
- 품목별 `파트실`, `개인별 보유`, `사무실`, `합계`를 한눈에 봅니다.
- `개인 입고`, `개인 출고`, `서울로 반납`, `서울에서 파트실로 택배`, `사무실 사용/보유`를 기록합니다.
- 기록을 수정하거나 삭제해도 변경 이력이 남습니다.
- 시리얼 번호가 필요한 품목은 언제든 따로 등록할 수 있습니다.
- 백업을 만들고, 필요하면 백업으로 복원할 수 있습니다.
- 오래된 사용내역 엑셀도 참고 기록으로 가져올 수 있습니다.

## 업무 기준

이 앱에서 사용하는 재고 기준은 요청자와 확인한 업무 용어를 따릅니다.

- `합계 = 파트실 + 개인별 보유 합계 + 사무실 보유/사용분`
- `개인 출고`: 파트실에서 빠지고 개인 보유가 늘어납니다.
- `개인 입고`: 개인 보유에서 빠지고 파트실이 늘어납니다.
- `서울로 반납`: 파트실에서 서울로 보내는 기록입니다.
- `서울에서 파트실로 택배`: 서울에서 파트실로 받는 기록입니다.
- `사무실`: 사무실에서 사용하는 물건이며, 개인이 가져간 것과 비슷하게 파트실에서 빠진 수량으로 봅니다.
- 시리얼 번호는 모든 품목에 필수는 아니며, 필요할 때만 등록합니다.
- 같은 시리얼 번호가 여러 번 등록되어도 막지 않습니다.

## 실행 방식

완성된 폴더를 Windows 컴퓨터에 복사한 뒤 `ChungbukInventory.exe`를 실행하는 방식입니다.

앱은 인터넷 서버가 아니라 사용자의 컴퓨터 안에서만 실행됩니다. 실제 재고 데이터와 백업은 실행 폴더 옆의 `user-data/` 폴더에 저장됩니다.

처음 전달할 때는 오래된 재고 데이터가 들어가지 않도록 빈 상태로 전달하고, 사용자가 직접 엑셀 파일을 가져와 시작합니다.

## 사용자 안내서

삼촌에게 전달할 사용 설명서는 아래 파일에 정리되어 있습니다.

```text
사용자_사용안내.md
docs/user-guide-ko.md
```

Windows에서 처음 확인할 때는 아래 문서를 함께 보면 됩니다.

```text
docs/windows-smoke-test-ko.md
docs/requester-acceptance-checklist-ko.md
```

## 개발 실행

개발 환경에서 실행하려면 Node.js 25 이상이 필요합니다.

```bash
npm start
```

실행 후 출력되는 로컬 주소를 브라우저에서 열면 됩니다. 개발 실행 시 데이터는 기본적으로 아래 위치에 저장됩니다.

```text
data/chungbuk-inventory.sqlite
data/backups/
```

## 검증

```bash
npm run check
npm test
npm run validate:portable
```

현재 테스트는 다음 흐름을 확인합니다.

- 입출고 재고 계산
- 음수 재고 차단
- SQLite 저장소와 트랜잭션
- 기록 수정/삭제/복원
- 백업 생성과 복원 검증
- 현재 재고 엑셀 가져오기
- 사용내역 `.xlsx` / `.xlsb` 참고 기록 가져오기
- UI 계약과 한국어 업무 용어
- Windows 배포 폴더 구조 검증

## Windows 전달용 폴더 만들기

개발 폴더에서 아래 명령을 실행하면 전달용 폴더가 만들어집니다.

```bash
npm run prepare:portable
```

결과 폴더:

```text
dist/chungbuk-inventory-portable/
```

Windows 전달 전에는 Windows용 Node 런타임이 아래 위치에 있어야 합니다.

```text
runtime/node/node.exe
```

GitHub의 `Build Windows portable app` 작업을 실행하면 Windows용 Node 런타임과
`ChungbukInventory.exe`가 이미 포함된 zip 파일을 받을 수 있습니다. 사용자는 압축을
풀고 exe만 실행하면 되며, 별도 빌드가 필요하지 않습니다.

개발자가 Windows 컴퓨터에서 실행 파일을 직접 다시 만들 때는 아래 파일을 실행합니다.

```text
BUILD_WINDOWS_LAUNCHER.cmd
```

그 다음부터는 사용자가 `ChungbukInventory.exe`만 실행하면 됩니다.

## 배포에서 제외하는 것

Git 저장소에는 실제 재고 데이터, 백업, 빌드 산출물, Windows 런타임을 넣지 않습니다.

제외 대상:

- `data/`
- `user-data/`
- `dist/`
- `runtime/`
- `runtime-downloads/`
- SQLite 데이터베이스 파일
- 로그 파일

실제 사용자의 재고 데이터가 저장소나 배포 zip 안에 섞이지 않도록 하기 위한 결정입니다.

## 아직 하지 않은 일

엑셀 내보내기는 아직 구현하지 않았습니다.

기존 엑셀 양식을 그대로 내보내려면 시트별 위치와 형식 매핑이 더 필요하므로, 현재 버전에서는 가져오기와 앱 내부 관리에 집중합니다.
